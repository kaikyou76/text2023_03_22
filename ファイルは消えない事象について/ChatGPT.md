# ✅ 想定される原因（発生頻度の高い順）

---

## **① 連携バッチ（Lambda / Glue / Step Functions / EC2 cron）が停止している**

毎月 1 日頃に自動取り込み → 正常なら S3 のファイルは消える
→ **消えない＝取り込み処理が走っていない**ことがほぼ確定です。

よくある停止理由：

* IAMロールの権限不足で失敗する
* Cron（スケジュール）が無効化された（手動ミス）
* Lambda のタイムアウト
* Lambda のメモリ不足
* Glue ジョブの失敗
* EC2 の cron サービスが止まった、もしくは EC2 インスタンス停止
* 運用チームが環境変更後に、連携処理の再設定を忘れた

---

## **② S3 のフォルダ名・ファイル名ルール変更による“認識不可”**

添付画像のファイル名：

### **Z_PCOUNT_202510.xlsx**

この場合、

* 連携バッチが **Z_PCOUNT_YYYYMM.xlsx** というフォーマットを厳密にチェックしている場合、
* **月単位のフォーマットズレ・未来の日付・末尾のスペース** などで “対象外” と判断されることがあります。

実務でとても多いミスです。

---

## **③ ファイルを置くべき S3 パスが誤っている**

添付画像のパス：

```
sghk-pi-data-prod / sghk / ExportZurich / AZ202 / 
```

実際には：

* AZ202 ではなく AZ_202 のように **アンダーバーが必要**
* ExportZurich ではなく export_zurich のように **小文字指定が必要**
* sghk フォルダの階層が 1 つ違う

などの “微妙なパス違い” が、連携失敗のあるあるです。

---

## **④ Zurich 側の受け取りジョブが停止している（アップ側は正常）**

チューリッヒの処理が：

* SFTP 取り込みジョブ
* データウェアハウス（DWH）読み込みジョブ
* API receive batch

いずれにせよ、受け取り側のバッチが止まると **S3 上のファイルは削除されません**。

---

## **⑤ AWS 側の権限変更で、連携バッチが S3 を読めなくなった**

最近 IAM の強化が入った環境でよく起こります。

必要権限：

```
s3:GetObject
s3:ListBucket
s3:DeleteObject
```

これが 1 つ欠けただけで、取り込みできなくなり、ファイルが残り続けます。

# 🔍 今すぐチェックすべきポイント（最短で原因を特定できます）

---

## **チェック1： 連携バッチがそもそも動いたか？**

AWS → CloudWatch Logs →

* Lambda（or Glue）のログ
* 実行失敗の有無
* タイムアウト・エラー内容

これを確認すればほぼ即特定できます。

---

## **チェック2：バッチのスケジュール（EventBridge）が無効になってないか？**

AWS → EventBridge → ルール

* 有効 / 無効
* 最近の実行状況

---

## **チェック3：S3 のパスが仕様と完全一致しているか？**

パス名、フォルダ名、ファイル名の規則を再確認。

担当チームの設計書にファイル名ルールが書いてあります。

---

## **チェック4：ファイル名フォーマット不一致**

「Z_PCOUNT_202510.xlsx」
↓
YYYYMM になっているが、処理が未来月・過去月を拒否する仕様の可能性。

---

## **チェック5：Zurich 側から“取得されていない”だけの可能性**

アップ側は正常、取得側の処理が落ちているパターン。
